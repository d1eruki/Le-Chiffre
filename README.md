# Le Chiffre

Сайт-квест в виде переписки: посетитель дополняет 16 фраз и после прохождения получает фотографию и подарочный код.

## Устройство проекта

- `index.html`, `styles.css`, `script.js` — интерфейс квеста.
- `questions.md` — таблица вопросов и ответов, отсортированная по главам; номера задают порядок в квесте. Это единственный источник вопросов для сборки. Альтернативные ответы разделяются `/`.
- `book/` — исходные страницы манги.
- `assets/final-photo.jpg` — исходная фотография подарка.
- `scripts/build-site.mjs` — сборка и шифрование; подарочный код хранится здесь в `GIFT_CODE`.
- `scripts/build-site.test.mjs` — проверки собранного квеста.
- `.github/workflows/pages.yml` — сборка, проверки и публикация на GitHub Pages.
- `dist/` — генерируемые файлы сайта, не хранятся в Git.

## Сборка и локальный запуск

Нужен Node.js 24 LTS или более новая совместимая версия. Сторонних пакетов нет.

```sh
node scripts/build-site.mjs
node --test scripts/build-site.test.mjs
python3 -m http.server 8000 --directory dist
```

Открой `http://localhost:8000`. Публикуй и раздавай только `dist/`. Прямое открытие корневого `index.html` не поддерживается: данные квеста появляются при сборке. Web Crypto требует HTTPS или локального адреса `localhost`.

## Публикация на GitHub Pages

В настройках репозитория выбери **Settings → Pages → Build and deployment → Source → GitHub Actions**. После отправки изменений в `main` workflow соберёт квест, проверит его и опубликует только `dist/`; также предусмотрен ручной запуск workflow.

Не используй публикацию корня ветки: там хранятся открытые ответы, код подарка и исходная фотография. Таблица, манга и исходники сборщика остаются в репозитории, но не входят в артефакт Pages.

## Как защищены ответы и подарок

Для каждого варианта ответа сборщик создаёт отдельную случайную соль и выводит ключ AES-GCM-256 через PBKDF2-SHA-256 с 600 000 итераций. Этот ключ шифрует случайный 32-байтовый фрагмент. Правильный ответ расшифровывает фрагмент; неверный ответ не проходит проверку целостности AES-GCM. Оба варианта одного вопроса открывают один и тот же фрагмент.

Из всех 16 фрагментов в порядке вопросов через SHA-256 получается ключ подарка. Код и фотография зашифрованы вместе в `reward.bin`; открытая фотография не публикуется. Фрагменты и подарок привязаны к случайному идентификатору сборки, поэтому смешивание данных разных сборок не работает. При обновлении страницы прохождение начинается заново.

Это защита от чтения ответов и подарка в опубликованных файлах, а не от офлайн-перебора: короткие слова можно подобрать, PBKDF2 лишь замедляет подбор. Изменение клиентского счётчика не заменяет недостающие части ключа. Получив все ответы, посетитель может расшифровать подарок самостоятельно и поделиться им.

Если репозиторий публичный, его содержимое и история доступны посетителям GitHub: шифрование сайта не скрывает находящиеся там ответы и подарок. Уже опубликованные ранее данные также не становятся секретными после новой сборки.

При каждой сборке соли, фрагменты и шифротексты создаются заново. Сборщик отказывается публиковать `dist/`, если в нём обнаружены файлы вне разрешённого списка; посторонние файлы автоматически не удаляются.
